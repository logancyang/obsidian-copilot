# Agent mentions

Asking one of the user's agents from a chat with `@`: that agent works in the background, and the chat's own agent brings its reply back.

## Sub-features

- mention-ask: in an agent's chat or a Copilot chat, a message that `@`-mentions an agent by name, such as `@Maya what do you think of this plan?`, hands that agent the request.
- mention-one-line: the chat's agent answers in one line, such as "Maya's reading it. I'll bring back what she says.", and its turn ends. The chat input is free while the other agent works.
- mention-view: choosing an ask card, a `Message from` card, or the agent's row in the [chat controls](chat-controls.md)' running agents list opens the two agents' conversation in place of the chat, read-only; it slides in from the right, and stays still when the system asks for reduced motion. One row heads it: Back, the asking agent's face and name (Copilot's mark in a Copilot chat), a double arrow, and the asked agent's face and name; it takes the place of the chat's own header. What the chat's agent sent comes first as a user's message; an answer it passed on is marked `Coco passed on your answer`. Below come the asked agent's steps, the files it changed, and its replies, scrolled to the latest; a later run starts below a `Continued at 10:21 AM` divider, its time written as message times are, with the full date and time as its tooltip. While it waits on the user, a banner says so and `Answer there` returns to the chat. There is no chat input: `You can only watch here. To tell Leo something, tell Coco.` Back or Escape returns to the chat.
- mention-tool-lines: in the chat agent's reply, asking an agent is one card from the moment the chat's agent starts writing to it: `Asking` with the agent's face and name and `…` until the message is sent, then `Messaged` with the face and name. Until the chat's agent has named who it asks, the card reads `Asking …` with a blank face; the face and name then fill in on the same card. It shows no message text; the name is brighter than the label. A message to an agent that already works reads `Messaged` too. The other things the chat's agent does with a mentioned agent are one line each with its face: `Checked Maya's progress`, `Passed your answer to Maya` and `Stopped Maya`, with nothing to open. A call that failed or named no agent the chat can ask shows its ordinary row once it ends.
- mention-several: one message can mention several agents, such as `@Maya @Leo does the $8k launch budget hold up?`. Each works on its own and sees nothing of the other's work; each ask gets its own `Messaged` card, in the order the chat's agent asked. The chat's agent passes each reply on as it comes back, without waiting for the others, and says who is still working; when the last one is back it can put the replies together.
- mention-keep-chatting: messages sent while the other agent works get their own answers.
- mention-relay: when the other agent is done, a new turn at the end of the chat passes its reply on, keeping its position as strong as it was, then adding the chat agent's own view.
- mention-reply-row: the turn starts with a card like the ask card: `Message from` with the other agent's face and name. It shows none of that agent's words in the chat; choosing it opens the conversation. A Files changed card for the files it changed follows, each row opening its diff, then the chat agent's own words. The agent's question reads `Message from` too. A run that ended with nothing to pass on reads `Maya stopped` or `Maya didn't finish` on the same card. The same shows in a Copilot chat.
- mention-continue: mentioning the same agent again in the same chat continues its conversation, so it remembers the earlier exchange.
- mention-redirect: a new instruction for an agent that still works, such as "Tell Maya to skip the outro.", reaches it in the same conversation. The chat's agent says it passed it on; on Codex and OpenCode models the other agent gets it after its current step.
- mention-question: when the other agent can't go on without the user, its question comes back as a turn that starts with the other agent's words, and the chat's agent asks it in its own words. The user answers in the chat input as usual; the chat's agent passes the answer on and the other agent carries on in the same conversation. Until the user answers, the other agent waits; asking about something else meanwhile gets its own answer.
- mention-progress: asking the chat's agent how the other agent is doing, such as "How's Maya doing?", gets an answer from that agent's progress so far: how long it has worked, what it has written and its latest steps, or the question it is waiting on. The other agent isn't interrupted.
- mention-permission: in a mode that asks before changes, the mentioned agent's request shows in this chat as a [permission card](permission-requests.md) with its face and name. The answer goes straight back to it; the chat's agent runs no turn for it. In `Plan` mode the mentioned agent changes nothing and says what it would have changed.
- mention-didnt-finish: when the other agent hits an error or its process ends, the chat's agent says it didn't finish, why, and how far it got. There is no Retry: telling the chat's agent to send it back, such as "Send Maya back to it.", continues the same conversation.
- mention-resume: mentioning an agent again after Obsidian restarts continues the conversation it had in that chat, so it remembers the earlier exchange. This holds for a chat with a note and for one without, such as a chat never saved with Autosave chat off.
- mention-stop: telling the chat's agent to stop the other agent, such as "Tell Maya to stop.", stops it at once. Its changes stay, and the chat's agent says how far it got, with a Files changed card for what it changed. Mentioning it again continues the same conversation.
- mention-delete-while-working: deleting an agent from its profile while it works for another chat stops it. The delete dialog says so in an orange line, such as "Maya is working in Coco's chat. Deleting stops it."; the chat's agent then says how far it got.
- mention-remember: a standing rule given through a mention, such as `@Maya from now on, flag video length first.`, is saved to the mentioned agent's own memory under the same rules as in its own chat, without a permission card. The relayed turn shows `Maya remembered` or `Maya replaced a rule` with the saved sentence under the `Message from` card, as in her own chat; the row opens her `MEMORY.md` at that rule, and the Files changed card leaves `MEMORY.md` out. The chat's own agent saves nothing for a rule meant for another agent. In `Plan` mode nothing is saved and the reply says so.
- mention-needs-setup: mentioning an agent whose model can't run on this device starts nothing, and no other model answers as it. The chat's agent says why, such as "Leo runs on OpenCode, which isn't set up on this device", and that another model can be picked in Leo's profile.
- mention-no-self: an agent never asks itself; its own name is plain text in its chat.
- mention-recall: later, in its own chat, the mentioned agent can tell who asked it, in which chat and when, what it was asked and what it answered, as part of its [earlier chats](agent-replies.md). Nothing new shows in Recent chats, the Navigator, View archived or its profile.

## How to get to it

- In the chat input of an agent's chat or a Copilot chat, type `@` and the agent's name, or choose `Agents` in the `@` list and pick the agent, then type the request and send.

## Driving it

All of these need a license that includes Copilot Teammates and at least two agents in the vault, one of them Maya.

- Ask: in a chat with another agent, send `@Maya what do you think of this plan? Six features in 90 seconds.` The agent answers in one line and its turn ends; Send is available again.
- Cards: after sending the mention, the chat agent's reply shows `Asking` with Maya's face and name, then `Messaged`. Nothing shows under the message that asked, and no clock shows anywhere. When the reply comes back, the new turn starts with `Message from` and her face and name, with none of her words.
- View: while Maya works, choose `Messaged Maya`. The conversation opens read-only, headed by one row with Back, the chat's agent, a double arrow and Maya; what the chat's agent sent her shows as a user's message, then her steps as they come in; no chat input shows. Choose Back: the chat returns. Choose `Message from Maya` once she replied: the same conversation opens with her reply in view. After a stop, send `Send Maya back to it.`, then open it again: a `Continued at <time>` divider separates her earlier work from the new run.
- Several agents: send `@Maya @Leo does the $8k launch budget hold up?`. `Messaged Maya` and `Messaged Leo` show as two cards. The first reply back is passed on while the running line still names the other, and the chat's agent says the other is still working; the second reply follows in a turn of its own.
- Keep chatting: while Maya works, send an unrelated question. It gets its own answer.
- Relay: when Maya is done, a new turn at the end of the chat shows `Message from` with Maya's face and name, then the chat's agent brings back her view. If she disagrees with the plan, the reply says so plainly.
- Files changed: in `Auto` mode, send `@Maya add one line to <note>`. The relayed turn shows Files changed with that note; its row opens the diff.
- Continue: after the relay, send `@Maya and the intro?`. Her answer builds on the first exchange.
- From a Copilot chat: in a chat with no agent, send `@Maya is this too long?`. The same one line, then the relay.
- Permission: in `Safe` mode, send `@Maya add one line to <note>`. `Permission required` shows Maya's face and "Maya wants to run …". Choose `Allow once`: the note changes, and the relayed turn shows Files changed with it. Send another and choose `Deny once`: the note stays unchanged. In `Plan` mode the note stays unchanged and no card shows.
- Redirect: while Maya works, send `Tell Maya to leave the intro alone.` The chat's agent says it passed it on, and Maya's reply follows the new instruction.
- Question: give Leo an instruction such as "Before changing any note, ask the user which month.", then send `@Leo reconcile the books`. The chat's agent asks which month. Answer `October.` The chat's agent says it passed the answer on, and Leo's reply follows it.
- Progress: while Maya works, send `How's Maya doing?`. The chat's agent says how far she got without stopping her.
- Didn't finish: while Maya works, end her agent's process. The chat's agent says she didn't finish and why. Send `Send Maya back to it.`; her reply builds on what she had done.
- Resume: after a relay, reload the plugin and open the chat from Recent chats. Choose `Message from Maya`: her reply shows below the note that her steps are no longer available; choose Back. Send `@Maya what did you tell me before?`. She recalls the earlier exchange. Repeat with Autosave chat off in a chat never saved: the same holds, and a run stopped before it replied still reads `Maya stopped`.
- Stop: send `@Maya check every claim in <note>, one by one`, then `Tell Maya to stop.` while she works. The chat's agent stops her, then says how far she got; the note keeps any change she made.
- Delete while working: send `@Maya …` with a long job, open Maya's profile, and choose Delete. The dialog shows `Maya is working in <agent>'s chat. Deleting stops it.` in orange. After Delete, the chat's agent says Maya was deleted and how far she got.
- Remember: in `Safe` mode, send `@Maya from now on, flag video length first.` No permission card shows; the relayed turn shows `Maya remembered` with the sentence under `Message from Maya`, and her `MEMORY.md` has the rule with a dated context line. The chat agent's own `MEMORY.md` is unchanged. Click the row: Maya's `MEMORY.md` opens at that rule. Reload the plugin and reopen the chat: the row is still there. Send `@Maya actually, flag the budget first instead.`: the row reads `Maya replaced a rule`. In `Plan` mode, send `@Maya from now on, open with the hook.`: nothing is saved and the reply says she can't save a rule in this mode. A new chat with Maya follows the saved rule.
- Needs setup: take Leo's coding agent off this device, then send `@Leo add up the October books.` from Maya's chat. Maya says Leo can't be asked here and why; no `Messaged Leo` card or reply from Leo follows.
- Itself: in Maya's own chat, send `@Maya hello`. Maya answers directly.
- Recall: after a relay, start a new chat with Maya and send `What have we talked about?`. She says who asked her, in which chat, and her answer; Recent chats and her profile show no new chat.

## Gotchas

- Without a license that includes Copilot Teammates, `@<name>` is plain text for the chat's own agent.
- A mentioned agent never changes its instruction, whatever the mode. A rule it saves applies from its next chat, as in its own chat; mentioning it again in the same chat continues a conversation that started with its earlier memory.
- A mentioned agent's work can be viewed only while Obsidian keeps its chat open: after a restart, or once the chat that asked it was shut down, the conversation says its steps from that run are no longer available, with what the agent sent back from that run, such as its question and its reply, below the note, until mentioning the agent again continues its conversation. A run that sent nothing back shows the note alone.
- The mentioned agent works in a chat no list shows: not in the [chat tabs](chat-tabs.md), Recent chats or the [Copilot Navigator](copilot-navigator.md).
- On Codex models, a chat can mention agents only if it was opened while Copilot Teammates was available: it keeps the tools it started with. On Claude and OpenCode models, an open chat gets the tools as soon as Copilot Teammates becomes available, and loses them when it stops being available.
- Closing Obsidian or shutting the chat down stops the mentioned agent; its reply never comes back.
- A mentioned agent asked while the license was valid keeps working once it is not, and its reply still comes back.
- The chat's note saves a stopped mention as stopped, whether the user stopped it or its agent was deleted.
- A settings change that restarts the chat's agent or the mentioned agent's waits until the mentioned agent's turn ends. While the mentioned agent waits for the user's answer, the restart goes ahead and stops it.
- Stopping the chat's own reply doesn't drop a mentioned agent's reply that is waiting; it comes back after the stop. Stopping the turn that passes the reply on ends it there.
- A mentioned agent's permission card stays when the chat's own reply is stopped. Stopping or deleting that agent, closing the chat, or closing Obsidian takes the card away, and the agent's request counts as turned down.
- On Codex models, `No, and tell Codex what to do differently` ends the mentioned agent's turn without a reply; the chat's agent says the user turned the request down.
- The chat's note keeps each mention's agent and how it ended, so it survives a restart. A chat without a note reads the same from the replies passed on to its agent; where a chat has a note, the note's record is the one shown. An agent that was still working when Obsidian closed is saved as not finished. In a chat without a note, a mention that passed nothing back before Obsidian closed, or one passed back by a Copilot version that didn't record how it ended, keeps its cards, but they don't open. Mentioning it again continues the conversation only while its agent still keeps it; otherwise a new conversation starts.
- The mentioned agent works in the chat's project folder, in the chat's mode, on its own model.
- When one agent's name starts another's, such as Maya and Maya Chen, `@Maya Chen` mentions only Maya Chen.
- On Claude, a reply that comes back while the chat's agent is still answering waits for that answer to end, so several replies come back one turn each. On Codex and OpenCode models the same holds: each waiting reply becomes its own next turn.
